점검일: 2026-10-17

| 개인정보처리방침·이용약관 | 미구현 | 운영 정책 페이지와 보관 기간이 없다. TEST에 검토용 초안만 추가했다. |

| 고객 신청 조회·수정·취소 | 미구현 | 고객 본인 확인 수단과 신청 상태 모델이 없다. |

## TEST에서 완료한 기본 개선

- 운영 홈과 분리된 `/TEST`에서만 메인 문구·과정 정보·신청 흐름 변경
- 풀장·요일·시간 원본을 `lib/booking-options.js` 한 곳에서 관리
- 밀양 오전부를 토·일에만 허용하고 요일 변경 시 무효 시간 자동 해제
- 휴장 안내 중인 두류풀장을 검증 단계에서도 거절
- 풀장·요일·시간 기본값 제거
- 과정 링크는 교육 분야만 유지하고 세부 과정과 일정은 미선택
- 과정 미정, 세부 과정 상담 결정, 일정 협의 상태를 정확한 선택과 분리
- 장소·요일·시간을 한 묶음으로 최대 8개의 대안 일정 입력
- 개인정보 입력을 마지막 단계로 이동
- 교육비·발급비·입장료·렌탈료 구분
- 필수 상담 처리와 선택 분석·마케팅 동의를 분리한 TEST UI
- 개인정보가 없는 일정 코드만 TEST 검증 API에 전송하고 이름·연락처는 전송하지 않음

## 운영 반영 전에 필요한 데이터 변경

현재 `customers`는 `preferred_pool_options`에 요일 배열과 시간 배열을 따로 저장한다. 대안 조합을 정확히 보존하려면 별도 `schedule_alternatives jsonb` 필드 또는 정규화된 일정 테이블이 필요하다. 기존 필드는 그대로 유지하고 새 필드를 추가한 뒤, 과거 데이터는 기존 의미로 읽는 호환 계층을 두는 방식이 안전하다.

신청 조회·상태 변경에는 최소한 다음이 추가로 필요하다.

- 신청 상태와 상태 변경 시각
- 중복 제출 방지용 idempotency key
- 고객 조회용 예측 불가능한 토큰과 추가 본인 확인 수단
- 수정·취소 가능 상태 및 변경 이력
- 동시 처리 충돌 방지를 위한 버전 또는 조건부 갱신

## 후속 후보 기능

### A. 가능한 일정 중심 수업 탐색

- 문제: 신청 후에야 가능 여부를 알 수 있다.
- 최소 범위: 패스나인 한 곳, 프리다이빙 한 과정의 날짜·회차별 가능 강사 표시.
- 필요 데이터: 실제 강사 일정, 풀장 잔여석, 가격, 확정 방식.
- 연결: 기존 공개 강사 API와 풀장 예약 현황 API.
- 결정 필요: 공개 가능한 강사 일정과 예약 확정 책임.

### B. 교육 진도 기록

- 문제: 강사가 바뀌면 이전 수업 내용과 다음 목표를 이어받기 어렵다.
- 최소 범위: 수업일, 진행 내용, 추가 연습, 다음 목표를 담당 강사와 고객만 열람.
- 필요 데이터: 수강 등록, 담당 관계, 기록 수정 이력, 사진·영상 동의.
- 연결: 강사 세션과 배정된 고객 조회 권한.
- 결정 필요: 보관 기간, 사진·영상 권한, 강사 변경 시 공유 범위.

### C. 트레이닝 잔여석·대기 신청

- 문제: 풀장 잔여석 조회와 실제 참여 신청이 분리돼 있다.
- 최소 범위: 한 풀장의 주간 회차, 참여 조건, 잔여 자리, 대기 등록.
- 필요 데이터: 회차 정원, 확정 참가자, 취소·대기 순번, 회당 비용.
- 연결: 현재 관리자 전용 풀장 예약 현황 조회.
- 결정 필요: 외부 예약 서비스와의 동기화, 결제·취소 정책, 지도 수업과 자율 활동 구분.
